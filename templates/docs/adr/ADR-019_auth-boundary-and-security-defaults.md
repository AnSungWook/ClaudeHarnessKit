# ADR-019: 인증은 한 자리가 들고, 보안 기본값은 닫힌 쪽이다 - 명시한 CORS, 좁힌 Actuator, 업로드 상한, 리다이렉트 제한

## Status

Accepted

## Date

2026-11-02

## Intent

인증 검사가 한 자리에만 있어 한 곳을 고치면 모든 창구에 걸리게 하고, 열어 둔 기본값 때문에 새는 길을 없앤다.

## Context

- 기존 상태: 인증 필터나 토큰 검사가 모듈마다, 컨트롤러마다 흩어져 있다. CORS 를 `*` 로 연다. Actuator 의 모든 엔드포인트를 노출한다. 업로드에 크기, 확장자 제한이 없다. 바깥 파일을 받을 때 리다이렉트를 무조건 따라간다.
- 문제점: 검사가 흩어지면 한 자리만 고쳐 다른 창구가 열린 채 남는다. `*` CORS 와 넓은 Actuator 는 진단에서 바로 지적되고 실제로 내부 정보를 낸다. 리다이렉트를 무조건 따라가면 사설 주소, 클라우드 메타데이터로 끌려가는 SSRF 가 된다.
- 제약 조건: 인증 방식(세션, JWT, 게이트웨이 헤더, 공유 비밀)은 프로젝트마다 다르다. 이 ADR 은 방식이 아니라 자리와 기본값을 정한다.

## Decision

**인증은 저장소마다 한 자리, 보안 설정은 닫힌 것이 기본이고 여는 것은 명시한다.**

- 인증 필터와 설정은 저장소마다 한 자리(한 모듈이나 한 패키지)에 둔다. 도메인 모듈과 컨트롤러에 인증 검사를 두지 않는다.
- 사람이 아니라 내부 시스템만 부르는 창구는 네트워크 격리와 공유 비밀 헤더 하나면 된다. 로그인과 역할이 없는데 무거운 인증 프레임워크를 다 세우지 않는다. 토큰은 비밀값이라 기본값 없이 받는다(ADR-003, ADR-013).
- 인증 실패 응답은 공통 오류 응답 모양이다(ADR-013).
- CORS 는 열지 않는 것이 기본이다. 열어야 하면 origin 을 명시한 목록으로 열고 `*` 는 쓰지 않는다.
- Actuator 같은 운영 엔드포인트는 `health`, `info`, 메트릭(`prometheus`)만 노출한다.
- 업로드는 확장자 허용 목록과 크기 상한을 둔다. 압축 파일이면 푼 총 크기와 항목 수 상한도 둔다.
- 바깥 파일 받기의 리다이렉트는 받는 곳에 따라 둘로 나눈다. 클라이언트는 ADR-018 이 정한다.
  - 받는 곳이 정해진 자리(우리 파일 서버, 정해진 파트너)는 그 도메인 허용 목록으로만 따라간다.
  - 받는 곳이 정해지지 않은 자리(사용자가 준 URL, 수집 대상 사이트)는 허용 목록 대신 사설 IP(10/8, 172.16/12, 192.168/16), 루프백, 링크 로컬(169.254/16, 클라우드 메타데이터)로 가는 요청을 막는다. 리다이렉트뿐 아니라 처음 주소도 본다.
- 요청자마다 갈리는 자원에서 남의 자원은 403 이 아니라 404 로 답한다. 있는지 없는지를 알려 주지 않는다.

### 체크리스트

- [ ] 인증 필터, 설정이 한 자리에만 있다
- [ ] CORS 에 `*` 가 없다(`allowedOrigins("*")`, `allowedOriginPatterns("*")`)
- [ ] Actuator 노출이 `health`, `info`, 메트릭뿐이다
- [ ] 업로드에 확장자 허용 목록과 크기 상한이 있다
- [ ] 바깥 파일 받기가 리다이렉트를 무조건 따라가지 않는다(허용 목록이나 사설 주소 막기)
- [ ] 남의 자원 접근이 404 다

### 안티패턴

| 안티패턴 | 올바른 패턴 |
|---------|-----------|
| 컨트롤러마다 `if (!token.equals(header)) return 401` | 인증 필터 한 자리 |
| `allowedOrigins("*")` | `allowedOrigins("https://admin.example.com")` |
| `management.endpoints.web.exposure.include: "*"` | `include: health,info,prometheus` |
| 업로드 크기 제한 없음 | `max-file-size`, 확장자 허용 목록, 압축은 푼 크기 상한 |
| `followRedirects(ALWAYS)` 로 사용자 URL 받기 | 사설, 루프백, 링크 로컬 주소를 처음과 리다이렉트마다 막는다 |
| 남의 주문 조회에 403 | 404 |

## 다른 언어에서

- 원칙(인증 한 자리, 닫힌 기본값, 여는 것은 명시, SSRF 막기)은 같다.
- TypeScript(Node): 인증은 미들웨어 한 자리. `cors()` 를 옵션 없이 쓰지 않고 origin 목록을 준다. multer 등 업로드에 `limits` 와 파일 필터. 바깥 받기는 주소를 풀어 사설 대역을 막는다.
- Python: FastAPI 는 의존성(`Depends`) 하나로 인증, `CORSMiddleware` 에 origin 목록. Django 는 미들웨어와 `ALLOWED_HOSTS`. 업로드 크기는 서버와 프레임워크 둘 다에서.

## Consequences

### 긍정적
- 인증을 고칠 때 한 자리만 보면 된다.
- 시큐어 코딩 진단에서 자주 나오는 지적(CORS, Actuator, 업로드, SSRF)이 기본값에서 막힌다.

### 부정적
- 여는 것마다 목록을 관리해야 한다.
- 사설 주소 막기는 프록시로 나가는 망에서 정상 요청을 막을 수 있어, 망 구성을 확인하기 전에는 막지 않고 경고 로그로 시작할 수 있다.
