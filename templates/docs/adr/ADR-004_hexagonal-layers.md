# ADR-004: 헥사고날 - 층은 역할로 정하고, 의존은 안쪽으로만 흐른다

## Status

Accepted

## Date

2026-10-30

## Intent

바깥(외부 API, 브라우저, 저장소, 화면, DB)이 바뀌어도 판단과 흐름은 그대로 두게 한다.

## Context

- 기존 상태: 서비스가 외부 라이브러리 응답 타입이나 JPA 엔티티를 직접 다루고, 어댑터끼리 서로 부르고, 도메인이 프레임워크 타입을 안다.
- 문제점: 저장소(파일 ↔ 오브젝트 스토리지), 데이터 출처(파일 ↔ API) 같은 바깥이 실제로 바뀌면 판단 코드까지 같이 흔들린다.
- 제약 조건: 이미 굳은 저장소의 패키지를 `domain/application/adapter` 로 통째로 옮기면 파일 이동과 이력 흔들림에 비해 얻는 것이 이름뿐이다.

## Decision

**층은 폴더 이름이 아니라 역할로 정하고, 의존은 안쪽으로만 흐른다.**

| 층 | 역할 |
|---|---|
| 도메인 | 값과 그 값의 판단(ADR-001) |
| 포트 | 바깥과의 약속(interface). 바깥과의 새 약속이 생길 때만 늘린다 |
| 서비스 | 흐름 - 포트와 도메인을 부르는 순서. 판단·조립을 들지 않는다 |
| 어댑터 | 포트 구현. 바깥 것(외부 라이브러리 응답, HTTP·JSON, 화면 요청·응답, 파일·DB)과 도메인 사이 번역 |
| 설정 | 어댑터를 골라 끼우는 조립 |

- 의존 방향: 어댑터 → 포트·도메인, 서비스 → 포트·도메인. 도메인은 다른 층도, 외부 라이브러리 타입(HTTP 클라이언트, 브라우저 자동화, JPA 엔티티 등)도 모른다.
- 서비스는 포트만 안다. 어떤 어댑터가 끼워졌는지 모른다.
- 어댑터는 다른 어댑터를 직접 부르지 않는다.
- 바깥 계약 타입(HTTP 요청·응답, 외부 API 응답, 영속 엔티티)과 도메인 모델을 섞지 않는다. 엔티티를 응답으로 그대로 내보내지 않고, 외부 응답 타입을 서비스로 넘기지 않는다.
  - 변환은 별도 Mapper 층에 모으지 않고 ADR-001 대로 만들어지는 쪽이 원본을 아는 방향 하나다: 응답은 `XxxResponse.of(domain)`, 도메인은 어댑터가 `Domain.of(...)` 로 만든다. 도메인은 DTO 를 모른다.
- 새 저장소는 폴더를 역할대로 만든다. 이미 굳은 저장소는 폴더를 옮기지 않고, 폴더 ↔ 역할 대응표를 문서에 두고 의존 방향만 지킨다.

### 체크리스트

- [ ] 도메인 패키지에 외부 라이브러리·프레임워크 import 가 없다
- [ ] 서비스가 어댑터 구현 클래스를 직접 참조하지 않는다(포트만)
- [ ] 어댑터가 다른 어댑터를 직접 부르지 않는다
- [ ] 외부 응답 타입이 어댑터 밖으로 나가지 않는다(도메인 값으로 번역)
- [ ] 서비스에 판단·조립이 아니라 호출 순서만 있다
- [ ] 컨트롤러가 엔티티를 그대로 응답하지 않는다(응답 타입의 `of(domain)`)
- [ ] 도메인이 요청·응답 DTO 나 엔티티 타입을 import 하지 않는다

### 안티패턴

| 안티패턴 | 올바른 패턴 |
|---------|-----------|
| 서비스가 `RestTemplate` 응답 DTO 를 그대로 받아 판단 | 어댑터가 도메인 값으로 번역해 포트로 돌려준다 |
| 도메인 record 가 `@Entity` 를 필드로 가짐 | 엔티티 ↔ 도메인 변환은 어댑터에서 |
| `S3StorageAdapter` 가 `HttpCatalogAdapter` 를 호출 | 둘 다 포트로 서비스가 순서대로 부른다 |
| 서비스가 `new FileStorageAdapter()` | 설정 층이 어댑터를 골라 주입 |
| 포트를 메서드마다 하나씩 늘림 | 바깥과의 새 약속이 생길 때만 포트를 늘린다 |

## 다른 언어에서

- 층과 의존 방향은 언어와 무관하다. 폴더 이름은 그 생태계 관례를 따르되 역할 대응표를 둔다.
- TypeScript(NestJS 등): 모듈 안에서 도메인·포트(인터페이스)·어댑터를 나누고, 도메인이 ORM 엔티티·HTTP 타입을 import 하지 않게 한다(dependency-cruiser 같은 도구로 검사 가능).
- Python: 패키지로 층을 나누고, 도메인이 프레임워크(FastAPI, SQLAlchemy 모델)를 import 하지 않게 한다(import-linter 로 검사 가능).

## Consequences

### 긍정적
- 바깥 교체(저장소, 외부 API)가 어댑터 하나와 설정 한 줄로 끝난다.
- 도메인과 서비스를 외부 없이 단위 테스트할 수 있다.

### 부정적
- 포트·어댑터·번역 코드가 늘어난다.
- 폴더와 역할이 다른 기존 저장소는 대응표를 따로 관리해야 한다.
