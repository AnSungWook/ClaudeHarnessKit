# ADR-010 예시: 주석은 왜를 적는다

[ADR-010](../../ADR-010_comments-explain-why.md) 을 배송비 계산, 송장 번호, 주문 취소 입구에 적용한 예다.

## 무엇을 보여 주나

무엇을 하는지는 이름(`FREE_DELIVERY_THRESHOLD`, `isRemoteArea()`, `TrackingNumber.of`)이 말하고, 주석은 코드만 봐서는 모르는 것 - 바깥 시스템의 제약, 겉보기와 다른 동작, 미룬 이유 - 만 적는다.
공개 입구(다른 기능이 부르는 `port/in`)는 계약을 문서 주석으로 적는다.

## 바른 모양

- `good/OrderCancellationUseCase.java` - 다른 기능이 부르는 입구라 입력의 뜻, 돌려주는 것(이미 취소된 주문이면 어떻게 되는지까지), 던지는 예외를 문서 주석으로 적는다.
- `good/DeliveryFee.java` - "무료 배송인데 왜 추가 요금이 붙나" 라는 겉보기와 다른 동작의 이유(택배사 계약)와, 무엇을 왜 미뤘는지 적은 `TODO`(이슈가 있어 번호도 달았다). 음수 배송비는 생성자가 막는다(ADR-002).
- `good/TrackingNumber.java` - 하이픈을 빼는 이유(조회 API 의 제약, 사람이 복사해 넣는 값)를 적는다.

## 어긋난 모양

- `bad/DeliveryFee.java` - 이력·작성자 주석, 코드를 풀어 쓴 주석, 이유 없이 무엇만 적은 주석, 주석 처리한 코드, 내용 없는 `TODO`.
- `bad/OrderCancellationUseCase.java` - 공개 입구인데 메서드 이름을 되풀이한 한 줄뿐이라, 부르는 쪽이 구현을 열어야 실패 갈래를 안다.

어긴 줄이 주석 자체라 `// ADR-010 위반:` 표시는 그 주석 바로 위 줄에 달았다.

## 무엇이 다른가

| 어긋난 모양 | 바른 모양 | 해당 체크리스트 줄 |
|---|---|---|
| `// 주문 금액이 5만 원 이상이면 기본 요금은 0원` | 주석 없이 `FREE_DELIVERY_THRESHOLD` 이름이 말한다 | 코드를 그대로 풀어 쓴 주석이 없다 |
| `// if (orderAmount >= ...) { surcharge = 0; }` | 지운다 | 주석 처리한 코드가 없다 |
| `// 2026-03-02 홍길동 수정` | 커밋 메시지(ADR-020) | 이력·작성자 주석이 없다 |
| `// 도서 산간이면 추가 요금을 더한다` | `// 택배사가 주문 금액과 상관없이 받는다. 그래서 무료 배송 기준을 넘어도 빼지 않는다.` | 겉보기와 다른 동작, 피하려는 문제에는 이유가 적혀 있다 |
| `// TODO 고칠 것` | `// TODO 추가 요금을 택배사별로 나눈다 - 두 번째 택배사 계약이 확정된 뒤(#142)` | (Decision: `TODO` 는 무엇을 왜 미뤘는지와 함께 적고, 이슈가 있으면 번호를 단다) |
| `// 주문 취소` 한 줄 | `@param`, `@return`, `@throws` 를 든 문서 주석 | 공개 API 에 계약이 적혀 있다 |

- 주석은 한 줄 한 문장으로 짧게 둔다. 주변 코드의 밀도와 말투에 맞춘다는 것도 ADR 의 결정이다.
- 문서 주석의 `@throws` 가 가리키는 예외는 공통 형제를 상속한 사유 예외(ADR-006)로, 이 예시에서는 이름으로만 쓴다.

## 기계 검사

이 ADR 을 막는 기계 검사는 없다. 리뷰가 체크리스트로 본다.
