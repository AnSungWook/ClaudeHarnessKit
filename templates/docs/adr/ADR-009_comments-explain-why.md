# ADR-009: 주석은 왜를 적는다

## Status

Accepted

## Date

2026-10-30

## Intent

주석이 코드와 어긋나 거짓말을 하는 일을 줄이고, 코드만으로는 알 수 없는 이유와 제약을 남긴다.

## Context

- 기존 상태: 코드가 하는 일을 한 줄씩 풀어 쓴 주석, 바꾼 이력을 적은 주석, 지운 코드를 주석으로 남긴 것이 섞여 있다. AI 가 만든 코드는 이런 주석을 특히 많이 단다.
- 문제점: 무엇을 하는지 적은 주석은 코드가 바뀔 때 같이 안 고쳐져 틀린 설명이 된다. 정작 "왜 이렇게 했나", "무엇을 피하려 했나" 는 남지 않는다.
- 제약 조건: 공개 API 의 계약(입력, 출력, 예외)은 사용하는 쪽이 코드를 열지 않고 알아야 하므로 적는다.

## Decision

**주석은 코드가 말하지 못하는 것만 적는다 - 왜, 무엇을 피하려고, 어떤 제약 때문에.**

- 무엇을 하는지는 이름(메서드, 변수, 타입)이 말하게 한다. 그것을 풀어 쓰는 주석은 달지 않는다.
- 적는 것: 다른 방법을 안 고른 이유, 외부 시스템의 제약, 겉보기와 다른 동작, 지켜야 할 순서, 성능·동시성 때문에 택한 모양.
- 공개 API(다른 모듈·저장소가 부르는 것)는 계약 - 입력의 뜻, 돌려주는 것, 던지는 예외 - 을 문서 주석으로 적는다.
- 바뀐 이력은 커밋 메시지에, 지운 코드는 git 에 둔다. 주석으로 남기지 않는다.
- `TODO` 는 무엇을 왜 미뤘는지와 함께 적고, 이슈가 있으면 번호를 단다.
- 주석의 밀도와 말투는 주변 코드에 맞춘다.

### 체크리스트

- [ ] 코드를 그대로 풀어 쓴 주석이 없다(`// i 를 1 늘린다`)
- [ ] 주석 처리한 코드가 없다
- [ ] 이력·작성자 주석이 없다(git 이 든다)
- [ ] 겉보기와 다른 동작, 피하려는 문제에는 이유가 적혀 있다
- [ ] 공개 API 에 계약이 적혀 있다

### 안티패턴

| 안티패턴 | 올바른 패턴 |
|---------|-----------|
| `// 주문을 저장한다` 위에 `orderRepository.save(order)` | 주석 없이 둔다 |
| `// 2024-03 홍길동 수정` | 커밋 메시지 |
| 지운 로직을 `/* ... */` 로 남김 | 지운다(git 에 있다) |
| 아무 설명 없는 `Thread.sleep(500)` | `// 외부 API 가 초당 2건 제한이라 간격을 둔다` |
| `// TODO 고칠 것` | `// TODO 재시도 상한을 설정으로 - 운영 값 확정 뒤(#123)` |

## 다른 언어에서

- 원칙은 언어와 무관하다. 문서 주석 형식만 다르다(KDoc, TSDoc, docstring).

## Consequences

### 긍정적
- 남은 주석은 코드가 바뀌어도 잘 안 틀린다.
- 읽는 사람이 이유와 제약을 바로 안다.

### 부정적
- 이름을 잘 짓는 부담이 커진다.
- "무엇" 과 "왜" 의 경계는 리뷰 판단에 기댄다.
